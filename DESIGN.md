# Shadow Leveling — Design System (Material 3)

> Android-native habit tracker built on **Material Design 3** ([m3.material.io](https://m3.material.io)).
> Theme: Solo Leveling × Atomic Habits. Player as user, System as app, Habits as Quests.
>
> This spec **conforms to M3**: tokens use the `md.sys.*` / `md.ref.*` naming convention, color roles map to the canonical M3 palette (primary / secondary / tertiary / surface / error + their containers and on-* pairs), typography uses the M3 type scale, components are M3 components with documented brand customizations declared via M3 component tokens, and motion uses the M3 easing/duration system.
>
> Self-contained: every token, role, and rule needed to build the product is in this document.

---

## 1. Concept & platform

- **Platform:** Android only. Material 3 Expressive (latest M3, 2024–2025 spec).
- **Implementation target:** Jetpack Compose with `androidx.compose.material3` ≥ 1.3, `MaterialTheme` + `M3Expressive` opt-ins where applicable.
- **Theme mode:** Dark theme is the **canonical** mode (the HUD aesthetic requires it). A light theme is generated for accessibility but is not the brand-default; system Day/Night still toggles correctly.
- **Dynamic color:** **Disabled.** This is a brand-locked theme. We provide a static M3 color scheme (see §2). Never call `dynamicDarkColorScheme()`.

## 2. Color — M3 color roles

### 2.1 Architecture

We follow the standard M3 token hierarchy:

```
Reference tokens (md.ref.palette.*)        ← raw tonal palettes
        ↓
System tokens (md.sys.color.*)             ← semantic roles (primary, on-primary, surface, …)
        ↓
Component tokens (md.comp.<component>.*)   ← component-specific overrides (rare)
```

App code and custom components **only ever read system tokens**. Never reference palette steps directly.

## 4. Shape — M3 shape tokens

M3 default uses generous radii (corner-large = 16dp, etc.). The Shadow Leveling brand requires a **flatter**, more angular shape system. We override the M3 shape tokens accordingly.

| Token | M3 default | **Shadow value** | Use |
|---|---|---|---|
| `md.sys.shape.corner.none` | 0 | 0 | Edge-to-edge surfaces |
| `md.sys.shape.corner.extra-small` | 4 | **2** | Buttons, chips, text fields, badges |
| `md.sys.shape.corner.small` | 8 | **2** | Cards (default) |
| `md.sys.shape.corner.medium` | 12 | **4** | Sheets, larger cards (used sparingly) |
| `md.sys.shape.corner.large` | 16 | **4** | Dialogs, top app bar containers (when filled) |
| `md.sys.shape.corner.extra-large` | 28 | **8** | Modal/full bottom sheets only |
| `md.sys.shape.corner.full` | pill | **pill** | Allowed only on FAB and avatar (see §6) |

**Hard rule:** No new components introduce a corner radius outside this token set. Default for new chrome: `extra-small` (2dp).

| `md.sys.elevation.level4` | 8 | `surface-container-high` (`#131C28`) | `shadow.glow.medium` |
| `md.sys.elevation.level5` | 12 | `surface-container-highest` (`#1A2230`) | `shadow.glow.intense` |

**Brand glow tokens** (used in place of M3 shadow):

| Token | Value |
|---|---|
| `shadow.glow.soft` | `0 0 12px rgba(74,189,255,0.25)` |

### 6.3 Branded motion patterns

All patterns must call `prefers-reduced-motion` (Compose: `LocalAccessibilityManager.areAnimationsEnabled`) and degrade as noted:

| Pattern | Spec | Reduced-motion |
|---|---|---|
| **Glitch-in** (panel reveal) | RGB-channel split → converge with single scanline sweep, `extra-long2` × `emphasized-decelerate` | Crossfade `medium1` × `standard` |
| **XP shimmer** | Linear gradient sweep along XP fill on increment, `long4` × `standard` | Width-only animation, no shimmer |
| **Quest complete** | Border flashes `primary` → `inverse-primary` over `medium4`, checkmark fills with `glow.soft` | Border tint fade only, `short3` |
| **Rank-up cinematic** | Fade-to-scrim → old badge dissolves → new badge materializes with particle burst → `[RANK UP]` toast, `shadow.cinematic` × `emphasized` | Static dialog with new badge; no particles |
| **Press state** | M3 state-layer overlay at 0.12 opacity (using `state-layers/state-layers.dark.on-surface`) for `short2` | unchanged |

**No Material ripple.** We replace M3's default ripple with a flat state-layer fade — Compose `LocalRippleConfiguration.provides(RippleConfiguration(color = Color.Transparent))` plus our own `Modifier.indication(StateLayerIndication)`.

## 9. Components

All components are **standard M3 components** with brand customization expressed as **M3 component-token overrides**. We list each with the deltas from default.

### 9.1 Top app bar (`md.comp.top-app-bar`)

- Variant: **Center-aligned** (M3) for dashboard, **Small** for sub-screens
- Container color: `md.sys.color.surface-container` (custom override; M3 default is `surface`)
- Container height: 64dp (M3 default)
- Title: `md.sys.typescale.title-large` for Small; `md.sys.typescale.headline-small` for Center-aligned
- Title casing: **UPPERCASE** for the screen-title role (brand override, applied via `text-transform`/`text.uppercase()`)
- Trailing icon: 24dp Lucide line icon, color `md.sys.color.on-surface`
- Bottom border (brand): 1dp `md.sys.color.outline-variant`

**Brand replacement of `PlayerHeader`:** the player header (LV/RANK/XP/HP/MP) is implemented as a **custom expressive top app bar** that extends `LargeTopAppBar`. Container 96dp. Below the bar a 1dp `outline-variant` divider.

> **Compose implementation note:** Do not apply `Modifier.height()` below 96dp on the PlayerHeader `Surface`. `headlineSmall` has a lineHeight of 32sp (not 24sp) — combined with the XP/HP/MP bar row (~14dp) and vertical padding, total content height exceeds 56dp or 72dp and will be silently clipped. 96dp is the verified minimum that fits all content without overflow.

### 9.2 Bottom navigation (`md.comp.navigation-bar`)

- M3 component name: **Navigation bar** (replaces M2 "bottom navigation")
- Container color: `md.sys.color.surface-container`
- Container height: 80dp (M3 default)
- Items: 5 (Quests · Stats · Shadow · Inventory · Settings) — M3 allows 3–5
- Indicator: pill, color `md.sys.color.secondary-container`, height 32dp
- Selected icon color: `md.sys.color.on-secondary-container` → **brand override:** `md.sys.color.primary` (with `glow.soft` drop-shadow on the icon)
- Unselected icon color: `md.sys.color.on-surface-variant`
- Label: `md.sys.typescale.label-medium`, always shown
- Top border (brand): 1dp `md.sys.color.outline-variant`

> **Compose implementation note:** Do not apply `Modifier.height()` to the `NavigationBar` composable. Its internal token (`NavigationBarTokens.ContainerHeight`) is 80dp and its item layout is measured against that. Forcing a smaller value clips icons and labels without a compile or runtime error. Let the component use its intrinsic height. The `indicatorColor` must be set to `Color.Transparent` — the default `secondaryContainer` pill renders a soft rounded chip that breaks the HUD aesthetic.

### 9.3 Card (`md.comp.elevated-card` / `outlined-card` / `filled-card`)

We use **outlined card** as the default — best fit for the HUD panel aesthetic.

- Container color: `md.sys.color.surface-container` at 85% alpha (brand override of M3's solid fill)
- Outline: 1dp `md.sys.color.outline-variant` rest, `md.sys.color.primary` when selected/active
- Corner radius: `md.sys.shape.corner.small` (2dp per §4)
- Elevation: `level0` rest, `level3` when selected (adds `glow.soft`)

**Brand decoration — corner brackets.** The Shadow Leveling "HUD Panel" is an outlined card with **decorative L-shaped brackets at all four corners**, drawn 2dp outside the card border, 12dp arms, 1.5dp stroke, color `md.sys.color.primary`. Brackets are decorative only (`importantForAccessibility=no`).

**Optional `[ TAG ]` chip** sits on the card's top edge (top: -10dp, right: 12dp): `shadow.typescale.system-tag`, color `md.sys.color.primary`, padding `0 6dp`, background `md.sys.color.background` (to mask the border under it).

### 9.4 Buttons (`md.comp.button`)

M3 has 5 button types. Mapping to brand:

| M3 type | Brand use | Container | Label | Outline |
|---|---|---|---|---|
| **Filled** | "ARISE", primary CTAs | `primary-container` (`#003547`) | `on-primary-container` (`#C9E9FF`) | none + `glow.medium` |
| **Filled tonal** | Secondary CTAs | `secondary-container` | `on-secondary-container` | none |
| **Outlined** | Default action button | transparent | `primary` | 1dp `outline` → `primary` on focus |
| **Text** | Tertiary / inline | transparent | `primary` | none |
| **Elevated** | **Not used** — conflicts with HUD aesthetic | — | — | — |

All buttons:
- Corner radius: `md.sys.shape.corner.extra-small` (2dp; brand override of M3 default `corner.full`)
- Label typography: `shadow.typescale.section` (UPPERCASE Rajdhani 500 + 0.15em tracking) — brand override of M3 `label-large` mixed-case
- Height: 40dp (M3 default)
- Min width: 64dp
- Icon size: 18dp leading, 4dp gap

### 9.5 FAB (`md.comp.fab`)

- Used for "Add Quest" only
- Variant: **Standard FAB** (56dp)
- Corner radius: `md.sys.shape.corner.extra-small` (2dp brand override of M3 `corner.large`)

- Container color: `md.sys.color.primary-container`
- Icon color: `md.sys.color.on-primary-container`
- Elevation: `level3` (with `glow.medium`)

### 9.6 Checkbox (`md.comp.checkbox`)

Used for the Quest checkbox.

- Size: 20dp (M3 default 18dp; brand bumps to 20dp for tap precision)
- Unselected outline: 1.5dp `md.sys.color.on-surface-variant`
- Selected container: `md.sys.color.primary`
- Selected check: `md.sys.color.on-primary`
- Selection adds `glow.soft`

Rank badges are **assist chips** with brand color overrides per rank.

- Container: transparent
- Outline: 1.5dp custom `rank-{e..s,national}.color`
- Label: `shadow.typescale.section` UPPERCASE, color matches outline
- Corner radius: `md.sys.shape.corner.extra-small` (2dp)
- B/A/S/National variants add `glow.soft` in the rank color

### 9.8 Progress indicators (`md.comp.linear-progress-indicator`)

- Used for XP, HP, MP bars
- Track color: `md.sys.color.surface-container-high`
- Indicator color: XP→`primary`, HP→`error`, MP→`tertiary`
- Track height: 4dp (M3 default; brand keeps)
- Active stop: brand omits the M3 active-stop dot for HUD cleanliness
- Adds `glow.soft` on the indicator fill

### 9.9 Snackbar (`md.comp.snackbar`)

System messages (`[QUEST CLEARED]`, `[ALERT]`) use snackbars.

- Container: `md.sys.color.inverse-surface`
- Text: `md.sys.color.inverse-on-surface`, `md.sys.typescale.body-medium`
- Action label: `md.sys.color.inverse-primary`
- Brand override: prefix the message with the system tag in `shadow.typescale.system-tag` color `inverse-primary`

### 9.10 Dialog (`md.comp.dialog`)

Used for confirmation (abandon quest), rank-up cinematic.

- Container: `md.sys.color.surface-container-highest`
- Corner radius: `md.sys.shape.corner.large` (4dp brand override)
- Headline: `md.sys.typescale.headline-small` UPPERCASE
- Supporting text: `md.sys.typescale.body-medium`
- Scrim: `md.sys.color.scrim` at 0.6 opacity

### 9.11 List item (`md.comp.list-item`)

Standard M3 list item used for inventory rows, settings rows. M3 default styling holds; only override is the list-item divider color → `md.sys.color.outline-variant`.

### 9.12 Custom: Hexagonal Stat Radar

No M3 equivalent. Implemented as a custom Compose `Canvas` component. Visual spec:
- 3 concentric hex rings, stroke `md.sys.color.outline-variant` at 50% alpha
- 6 axes from center, stroke `md.sys.color.outline-variant` at 60% alpha
- Filled stat polygon, fill `md.sys.color.primary` at 20% alpha, stroke 1.4dp `md.sys.color.primary`
- Vertex dots: 2.5dp circles, `md.sys.color.on-primary-container`

- Axis values: `shadow.typescale.stat-number` size 12, `md.sys.color.on-surface`

## 10. Iconography

- **Icon set:** Material Symbols ([fonts.google.com/icons](https://fonts.google.com/icons)) — **Outlined** style only.
- Optical size 24, weight 400, fill 0, grade 0.
- **Filled icons forbidden** — they read too solid against the void surface.
- Color: `md.sys.color.primary` (active) or `md.sys.color.on-surface-variant` (inactive). Never colorful.

### 10.1 Stat icons (custom — not in Material Symbols)

Custom 24dp 1.5dp-stroke SVGs for: STR (dumbbell), INT (brain), AGI (lightning), SEN (eye), VIT (heart-shield), PER (target). Stroke matches Material Symbols Outlined weight 400.

### 10.2 Emoji policy

- **Never** in System-authored copy (system messages, microcopy, snackbars, dialogs).
- **Allowed** verbatim inside user-created habit titles (e.g. "🏃 Morning Run").

## 11. Voice & microcopy

The System speaks in **second person**, tersely, never warm. Igris (Shadow Guide) shares the same voice — slightly disdainful, never cheerleading.

### 11.1 System tags (use verbatim)

`[SYSTEM]` · `[QUEST REGISTERED]` · `[QUEST CLEARED]` · `[QUEST FAILED]` · `[ALERT]` · `[PENALTY APPLIED]` · `[RANK UP]` · `[SHADOW GUIDE]:`

### 11.2 Examples — KEEP

- `[QUEST REGISTERED] — Daily run, 5km. Reward: 45 XP, AGI +3.`
- `[QUEST CLEARED] — +45 XP. AGI: 84 → 87.`
- `[ALERT] — Habit dormancy in 1 day. Take action.`
- `[SHADOW GUIDE]: Performance down 15% from yesterday. Recommend completing Running quest.`
- `ARISE.` ← used exactly once, at S-rank promotion.

### 11.3 Examples — REJECT

- ❌ `Hey buddy! Looks like you're slipping! 😊`
- ❌ `Great job! You completed your quest!`
- ❌ Emoji, confetti, exclamation points (except the cinematic `ARISE.`).

### 11.4 Numbers in copy

- Always with units (`+45 XP`, `AGI +3`, `5km`, `23:59`).
- Stat changes shown as `before → after`.
- Always tabular.

## 12. Accessibility (M3 mandatory)

Per M3, accessibility is non-negotiable.

| Requirement | Spec |
|---|---|
| Color contrast | All `on-*` pairs verified ≥ 4.5:1 (text) / 3:1 (icons & large text) against their containers. Verified by Material Theme Builder. |
| Touch targets | ≥ 48×48dp |
| TalkBack | Every actionable element has a content description. Decorative brackets, scanlines, glow are `importantForAccessibility=no`. |
| Reduced motion | Honor system setting; degrade per §6.3. |
| Large fonts | All scales scale with `sp`; layouts tested at 200% font scale. |
| Color independence | Status (success/warning/danger/quest-complete) is **never communicated by color alone** — always paired with a system tag, icon, or text label. |

## 13. Dark theme defaults (M3 conformance checklist)

This section confirms M3 dark-theme rules ([m3.material.io/styles/color/dark-theme](https://m3.material.io/styles/color/dark-theme)):

- ✅ Avoid pure-white text on pure-black: `on-surface` is `#E6F1FF`, `surface` is `#05070A` (near-black, not pure).
- ✅ Use desaturated primary: brand primary `#4ABDFF` is desaturated cyan-blue, not vivid.
- ✅ Use surface elevation tint not white-shadow: handled via tonal elevation tokens (§5).
- ✅ Reduce eye strain on large surfaces: 90% of any screen is a low-tone surface (`background` or `surface`).
- ✅ Maintain depth via tonal elevation: `surface-container-low/.../highest` map to elevation levels 1–5.

---

## 14. Hard rules — never violate

1. **All color, type, shape, motion values come from M3 system tokens** (or documented brand-extension tokens). No raw hex in component code.
2. **Corner radii use the M3 shape scale only** — and that scale is the brand-overridden version in §4 (max 8dp).
3. **No drop shadows** on level3+ — replace with `shadow.glow.*`.
4. **No Material ripple** — replace with flat state-layer fade.
5. **No dynamic color** (`dynamicDarkColorScheme()` is forbidden).
6. **No emoji** in System-authored copy.
7. **No filled Material Symbols.** Outlined only.
8. **Numbers always tabular** (`featureSettings = "tnum"`).
9. **Section labels always UPPERCASE** with tracking ≥ 0.15em.
10. **Status never color-only** — always paired with tag, icon, or text.
11. **Touch target ≥ 48dp** even when visual hit area is smaller.
12. **Honor `prefers-reduced-motion`** for every animation.

## 16. Substitutions, deviations, open questions

This system **deviates from M3 defaults** in four documented places. Each is intentional and brand-owned:

1. **Shape scale** — flatter than M3 default (max 8dp vs M3's 28dp). §4.
2. **No ripple** — replaced with flat state-layer fade. §6.3.
3. **No drop shadow at elevation ≥ 3** — replaced with brand glow tokens. §5.
4. **Button label casing** — UPPERCASE override of M3's mixed case. §9.4.

All other surfaces, components, behaviors are **standard M3** with token-driven theming.
